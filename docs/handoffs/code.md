## Conflicts in `dist/` (generated files)

`dist/` is generated by `npm run build`. Never hand-merge a conflict in `dist/`, and never edit a file in it by hand. When a cherry-pick or merge conflicts in `dist/`:

1. Take master's version: `git checkout --ours dist/` (during a cherry-pick onto master, `--ours` is your branch, which is master plus your work so far).
2. Resolve the conflicts in source files only (anything outside `dist/`) as the task says. If a source file conflicts, stop and report the file names to Marcos. Do not guess.
3. Run `npm run build`. It rewrites `dist/`. The rebuilt output decides its contents.
4. Run `npm run build` a second time, then `git diff --exit-code -- dist`. It must print nothing. If it prints anything, stop and report.
5. Commit the rebuilt `dist/` with the source. Say in the PR body that `dist/` was rebuilt after a conflict.

This rule is Hub's standing call (2026-11-20, Marcos's coordinator). It applies to every task.
